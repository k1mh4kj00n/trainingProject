# MVP PRD 작성

이 문서는 개발팀이나 AI 빌더가 바로 개발에 착수할 수 있는 수준이어야 한다. 후속 질문 없이 구현 가능할 만큼 정밀하게 작성하라.

## 사전 확인

작성 전 다음 파일이 있는지 확인하고, 있다면 내용을 참조한다:
- `./docs/린캔버스-lean-canvas.md`
- `./docs/페르소나-persona.md`
- `./docs/경쟁사분석-competitors.md`
- `./docs/검증-*-validation.md`

없다면 사용자에게 "먼저 린 캔버스나 검증을 진행하시는 게 좋습니다"라고 권유한다.

## PRD 구조

### 1. 문서 정보
- 제품명
- 버전 (v0.1 등)
- 작성일
- 작성자

### 2. 한 줄 요약
- 30단어 이내로 "이 제품이 무엇이고 누구를 위한 것인지"

### 3. 문제 정의
- 해결하려는 문제 (증거 기반)
- 현재 대안과 그 한계
- 이 문제를 해결해야 하는 이유

### 4. 솔루션 개요
- 핵심 가치 제안
- 솔루션 작동 방식 (3~5문장)
- 다른 솔루션과의 차별점

### 5. 타겟 사용자
- 메인 페르소나 요약
- 사용자 시나리오 (Day in the Life)

### 6. 기능 범위 (가장 중요)

**MoSCoW 우선순위로 분류:**

#### Must Have (MVP 필수)
첫 2주 스프린트에 반드시 들어가야 할 기능. 5~7개로 제한.
각 기능마다:
- 기능명
- 설명 (3~5문장)
- 사용자 스토리: "[페르소나]로서, 나는 [목표]하기 위해 [기능]을 원한다."
- 인수 조건 (Acceptance Criteria) — 테스트 가능한 형태로
- 구현 복잡도: 🟢 Low / 🟡 Medium / 🔴 High

#### Should Have (다음 스프린트)
중요하지만 MVP에는 빠질 수 있는 기능

#### Could Have (있으면 좋음)
시간이 남으면 고려할 기능

#### Won't Have (이번 버전에서 제외)
**제외 이유를 반드시 명시**. 가장 중요한 섹션. 무엇을 안 만들지 명확히 하지 않으면 스코프가 무한 확장된다.

### 7. 사용자 플로우
주요 시나리오 2~3개를 단계별로 기술:
1. 진입 → 가입/온보딩 → 핵심 기능 → 결제/완료
- ASCII 다이어그램 또는 단계별 리스트

### 8. 기술 요구사항 (간략)
- 플랫폼 (웹/iOS/Android)
- 권장 기술 스택 (Next.js + Supabase 등)
- 외부 의존성 (결제, SMS, 메일 등)
- 데이터 모델 핵심 엔티티 (3~5개)

### 9. 성공 지표 (KPI)
- North Star Metric 1개
- 보조 지표 3~4개
- 각 지표마다 측정 방법과 목표 수치 명시
- "사용자 만족도 향상" 같은 모호한 표현 금지

### 10. 리스크와 가정
- 핵심 가정 5가지 (각각 검증 방법 포함)
- 식별된 리스크와 완화 방안

### 11. 타임라인
- Week 1: ...
- Week 2: ...
- Week 4 마일스톤: 첫 사용자 10명 확보
- Week 8 마일스톤: 유료 사용자 첫 1명

### 12. AI 빌더용 프롬프트 (부록)

Bolt.new, Lovable, v0 등에 바로 붙여넣을 수 있는 프롬프트:
```
Create a [기술 스택] application for [한 줄 요약].

Pages:
1. [페이지명] - [목적]
2. ...

Core features:
- [기능1]
- [기능2]

Design: [톤앤매너]
Auth: [방식]
Database: [핵심 테이블]
```

## 출력 규칙

- 한국어로 작성 (단, AI 빌더용 프롬프트 부록은 영어)
- 결과를 `./docs/mvp-prd.md`로 저장
- 모호한 표현 금지. 모든 항목에 구체적 수치/예시 포함.
- 가정인 부분은 `[가정]` 태그로 표시
- 작성 후 사용자에게 검토 요청
